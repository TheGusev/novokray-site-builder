# Граф перелинковки, итоговый SEO-аудит и разбор конкурентов

Три связанные задачи: сначала строим проверяемый граф связей, затем на его данных формируем отчёт, параллельно — конкурентный разбор по Новосибирску.

## 1. Граф внутренней перелинковки (код + тесты)

Новый модуль `src/data/linkGraph.ts`: собирает узлы и рёбра из существующих источников
(`servicesIndex.ts`, `landings.ts`, `cities.ts`, `districts.ts`, `interlinking.ts`, `blog`), без ручных списков.

```text
/services/:slug ──┬─ hasPart ──> /obrabotka/:pest-v-object
                  ├─ geo ──────> /gorod/:city, /raion/:district
                  ├─ info ─────> /blog/:slug
                  └─ nav ──────> /services, /price, /category/...
```

Узел: путь, intent, главный запрос, входящие/исходящие рёбра, тип анкора.

Автопроверки (`src/data/__tests__/linkGraph.test.ts`):
- нет страниц-сирот (0 входящих) и тупиков (0 исходящих);
- глубина от главной ≤ 3 клика для любой посадочной;
- коммерческий анкор ведёт только на страницу услуги, гео-анкор — только на гео-страницу (правило из `interlinking.ts`);
- нет каннибализации: один запрос из `semanticCore.ts` — одна цель (перепроверка на данных графа, а не только на карте запросов);
- взаимность: если услуга ссылается на посадочную, посадочная возвращает ссылку на услугу.

## 2. Согласованность разметки (hasPart / ItemList / OfferCatalog)

Проверяем и достраиваем связи в JSON-LD по всем 130+ маршрутам:
- `Service.hasPart` → объектные посадочные, `isPartOf` обратно;
- `OfferCatalog.itemListElement` → `Offer` каждой позиции прайса;
- `ItemList` каталогов и категорий → элементы в правильном порядке `position`;
- `FAQPage.mainEntityOfPage` и `BreadcrumbList` привязаны к `@id` страницы;
- `potentialAction`/`OrderAction` на коммерческих страницах.

Расширяем `scripts/check-static-schema.mjs`: обход статического экспорта, разбор `@graph`, отчёт о битых `@id`-ссылках. Прогон входит в проверку сборки.

## 3. Итоговый SEO-аудит (отчёт с оценкой 100)

Файл `AUDIT.md` в корне проекта + краткая версия в чате. Разделы с оценкой и статусом каждого пункта:

| Блок | Что проверяем |
| --- | --- |
| Роутинг | все маршруты отдают 200, canonical самореферентный, нет дублей и битых ссылок |
| Пагинация | блог/каталог: rel-навигация, canonical, отсутствие индексации дублей |
| Алерты и формы | валидация, состояния ошибок, доставка лидов (сервер + резервный канал) |
| Перелинковка | результаты графа из п.1 |
| Разметка | результаты проверки из п.2 |
| Семантика | покрытие ВЧ/СЧ/НЧ/СНЧ, каннибализация |
| Скорость и мобильная выдача | вес страниц, ленивые медиа, поведение на 393px |
| GEO/ИИ-выдача | llms.txt, прямые ответы, speakable |

По каждому пункту: балл, «выполнено / не выполнено», что именно осталось.

## 4. Конкурентный разбор топ-10 по Новосибирску

Источники: данные Semrush (видимость, ключи, топ-страницы, гэпы) плюс разбор структуры посадочных у профильных СЭС Новосибирска.

По каждому конкуренту фиксируем: структуру URL, типы посадочных (услуга / объект / гео), объём семантики, наличие прайса, разметки, кейсов, видео. На выходе — таблица сравнения и список точек роста, отсортированный по влиянию на топ-1, с оценкой трудозатрат.
