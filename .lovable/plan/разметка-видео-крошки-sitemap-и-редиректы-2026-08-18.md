# Разметка видео, крошки, sitemap и редиректы

## Что уже проверено (факты)

- На проде `https://dez-federation.ru/price` отдаёт **301 на `/price/`** (со слэшем), а в HTML этой страницы `canonical` указывает на `/price` (без слэша). Прямое противоречие: робот приходит на один URL, канонический — другой.
- `/price/index.html` отдаёт **200** — третий дубль той же страницы.
- Правило нормализации (301 на URL без слэша) сейчас есть только в `SERVER_DEPLOYMENT.md`; на сервере оно не применено, а деплой умеет автоматически чинить только блок `/api/...`.
- В sitemap на проде 108 URL: нет `/video`, нет отдельного видео-sitemap.
- BreadcrumbList уже есть на услугах, гео (город/район), категории, блоге и статических страницах. Нет на `/video`, `/faq`, `/kp`, `/docs/$slug`.
- VideoObject уже содержит name, description, thumbnailUrl, contentUrl, uploadDate, duration, width/height, publisher — обязательный минимум Google закрыт.

## Что сделаю

### 1. Редиректы и единый канонический URL (главное)
Приводим прод к варианту **без трейлинг-слэша** (совпадает с canonical и sitemap):
- В `.github/workflows/deploy.yml` добавить автоматическую вставку блока нормализации в конфиг nginx (та же схема с бэкапом и откатом при `nginx -t`, что уже работает для `/api/`), потому что доступа по SSH нет.
- Убрать действующее правило, добавляющее слэш, чтобы не получилось цикла `/price -> /price/ -> /price`.
- Итог: `/price/` и `/price/index.html` → 301 на `/price`; корень `/` остаётся собой; статика и `/api/` не затрагиваются.
- После деплоя прогнать проверку всех типов URL (главная, услуги, гео, районы, категории, блог, docs, video, kp) в четырёх вариантах: без слэша, со слэшем, с `index.html`, с параметрами — и убедиться, что нет 404, 302 и цепочек длиннее одного шага.

### 2. Валидация VideoObject
- Прогнать разметку всех страниц с видео через официальный валидатор Schema.org и через проверку требований Google (обязательные и рекомендуемые поля), результат вынести в отчёт.
- Дополнить рекомендуемыми полями, которых нет: `embedUrl`, `thumbnail` как `ImageObject` с размерами, `regionsAllowed`. `interactionStatistic` не добавляю — реальных цифр просмотров нет, выдумывать нельзя.
- Требования Яндекса по видеоразметке проверю по спецификации; сам кабинет Вебмастера от вашего имени я открыть не могу — если там всплывут предупреждения, пришлите скрин, поправлю точечно.

### 3. BreadcrumbList на оставшихся страницах
Добавить цепочки на `/video`, `/faq`, `/kp`, `/docs/$slug` (Главная → раздел → страница), с абсолютными URL и совпадением с видимыми крошками.

### 4. Sitemap
- Добавить недостающие посадочные (`/video`, индекс документов, все хабы и категории) — список маршрутов сверить автоматически, чтобы не осталось пропусков.
- Разбить на индекс: `sitemap.xml` → `sitemap-pages.xml`, `sitemap-blog.xml`, `sitemap-video.xml`.
- `sitemap-video.xml` — с namespace `video:` (заголовок, описание, постер, файл, длительность) по всем роликам.
- Пагинация блога: `/blog?page=N` сейчас закрыты в `robots.txt` и имеют canonical на `/blog`. Класть такие URL в sitemap нельзя — это противоречие. Сделаю правильный вариант: страницы пагинации остаются вне sitemap и проходимы для робота по ссылкам `rel=prev/next`, а все статьи целиком попадают в `sitemap-blog.xml`. Если нужно именно индексировать пагинацию — скажите, тогда снимем запрет в robots, поставим self-canonical и добавим её в sitemap.
- `lastmod` оставляю только там, где есть настоящая дата (статьи); для остальных страниц дату сборки не подставляю.

### 5. Проверки
- Расширить автотест разметки: обязательные поля VideoObject, наличие BreadcrumbList на каждой публичной странице, корректные позиции и абсолютные URL.
- Новый тест по sitemap: каждый URL отвечает 200 без редиректа и имеет self-canonical; в sitemap нет URL, закрытых в robots.
- Скрипт проверки редиректов на проде — прогон после публикации, отчёт в чат.
