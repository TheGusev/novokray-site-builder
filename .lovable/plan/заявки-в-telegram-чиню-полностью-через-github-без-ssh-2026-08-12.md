# Заявки в Telegram: чиню полностью через GitHub, без SSH

Токен лежит в GitHub Secrets, бот в группе, доступа к серверу у вас нет. Значит вся настройка и диагностика должны выполняться самим деплоем и печататься в логе GitHub Actions понятным текстом.

Сейчас деплой умеет только «подставить токен, если файл пуст» и не трогает nginx — а именно nginx (отсутствие проксирования `/api/lead`) и незаполненный env — самые вероятные причины тишины в группе.

## Что делаю в деплое (`.github/workflows/deploy.yml`)

1. Токен: если `secrets.TELEGRAM_BOT_TOKEN` задан, деплой записывает его в `/etc/dez-federation/lead.env` всегда, когда там нет ровно такого же значения (сейчас только при пустом). Плюс дописывает `TELEGRAM_CHAT_ID` и `LEAD_API_PORT`, права 600.
2. nginx: деплой сам проверяет, есть ли в конфиге сайта проксирование `/api/(lead|dadata)`. Если нет — добавляет готовый блок перед `location /`, делает `nginx -t` и при успехе `reload`; при ошибке возвращает старый конфиг из бэкапа и пишет об этом в лог.
3. Сервис: устанавливает/обновляет юнит, `enable --now`, ждёт готовности порта 8787.
4. Проверки с человеко-читаемым выводом в конце лога Actions:

```text
Токен в lead.env ............ есть
Сервис lead-api ............. работает
Локально /api/lead .......... ok
Через nginx /api/lead ....... ok
Тестовая заявка в Telegram .. отправлена (пометка «Проверка канала»)
```

Если что-то из этого «нет», деплой печатает причину простыми словами (бот не в группе, токен неверный, nginx не проксирует) и последние 30 строк лога сервиса. Сайт при этом всё равно выкладывается.

## Страховка, чтобы заявки не терялись

- `server/lead-api.ts`: каждая принятая заявка сначала дописывается в файл `/var/log/dez-federation/leads.jsonl`, и только потом уходит в Telegram. Даже если Telegram недоступен, заявка сохранена.
- Если Telegram отверг сообщение, сервис повторяет отправку через 5 и 30 секунд.
- Ответ сайту остаётся `{"ok":true}`, если заявка записана, — посетитель всегда видит «принято».

## Что нужно от вас

Ничего, кроме нажатия «Опубликовать»/push. После прогона Actions пришлите мне последний блок лога (сводку) — по нему я добью остаток, если что-то останется красным.

## Технические детали

- Тестовая заявка идёт с `formName: deploy-check` и приходит в группу с пометкой «🧪 Проверка канала» — так вы сразу увидите, что канал живой.
- Правка nginx идемпотентна: повторные деплои ничего не дублируют, перед изменением делается бэкап конфига с датой.
- Файл `leads.jsonl` пишется с ротацией по размеру (10 МБ), права 600.
