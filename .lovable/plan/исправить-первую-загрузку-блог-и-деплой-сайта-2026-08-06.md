# Исправить первую загрузку, блог и деплой сайта

## Подтверждённые причины

- На боевом домене при `DOMContentLoaded` высота основного содержимого составляет около 1069 px, а через 5 секунд — около 8591 px. Поэтому подвал сначала оказывается в первом экране, а после выполнения клиентского кода резко уезжает вниз. Это не связано с PDF: PDF-библиотеки не загружаются на главной.
- Главная страница всё ещё синхронно импортирует полный каталог услуг и изображения. Кроме того, крупные блоки страницы фактически достраиваются после запуска JavaScript, хотя сайт развёртывается как набор статических страниц.
- Таблица в статье хранится в корректном Markdown-виде, но текущий самописный парсер распознаёт разделитель таблицы слишком строгим регулярным выражением. Поэтому строки выводятся как обычные абзацы.
- В библиотеке сайдбар сделан `sticky`, но не ограничен по высоте и содержит несколько длинных блоков. На невысоком экране нижняя часть визуально наезжает на соседнее содержимое.
- Деплой сначала полностью очищает рабочий каталог сайта, а затем копирует новую сборку. Между этими действиями nginx может отдавать пустой каталог или fallback с неполным набором файлов.
- Сжатие HTML на сервере уже включено, но опубликованная версия от 2 августа всё ещё отдаёт CSS размером около 119 КБ; для хешированных ресурсов нужно отдельно проверить долгий кеш и отсутствие смешивания файлов разных сборок.

## Что изменить

1. **Стабилизировать первый экран и убрать появление подвала**
   - Проверить результат статической генерации главной и добиться, чтобы полный каркас страницы присутствовал в исходном HTML до гидратации.
   - Зарезервировать стабильную высоту hero и первого контентного блока на мобильных и ПК.
   - Добавить preload для фонового изображения hero и высокий приоритет только этому LCP-изображению.
   - Убрать из главной синхронные зависимости, которые не нужны первому экрану; тяжёлые интерактивные секции подключать отдельными чанками без изменения их внешнего вида.
   - Упростить тяжёлую анимацию фонового изображения на слабых мобильных устройствах и сохранить вариант без анимации для `prefers-reduced-motion`.

2. **Исправить библиотеку блога**
   - Переделать desktop-компоновку на устойчивую grid-сетку с `minmax(0, 1fr)` для колонки статей.
   - Оставить sticky только для компактной навигации по разделам либо ограничить sticky-блок высотой окна и внутренней прокруткой; документы и теги не должны перекрывать карточки.
   - Проверить ширины карточек, длинные названия категорий и состояние на границе desktop/tablet.

3. **Исправить Markdown-таблицы во всех 50 статьях**
   - Заменить строгую проверку на разбор стандартного Markdown-разделителя с пробелами и выравниванием.
   - Нормализовать количество ячеек в строках и корректно обрабатывать начальный/конечный `|`.
   - Оформить таблицы как читаемый адаптивный блок: заголовок, чередование строк, горизонтальная прокрутка на узком экране.
   - Добавить тесты парсера для таблицы со скриншота и нескольких вариантов синтаксиса, чтобы ошибка не вернулась в смежных статьях.

4. **Сделать деплой без перерыва в работе**
   - Собирать релиз в новый временный каталог, проверять наличие `index.html`, CSS/JS, `robots.txt`, sitemap, PDF и шрифтов.
   - Переключать готовую сборку в рабочий каталог атомарно, а не удалять действующий сайт перед копированием.
   - После переключения запускать контрольные HTTP-проверки главной, блога, статьи, PDF и статического ресурса; при ошибке не оставлять сервер с неполной сборкой.
   - Сохранять `.well-known` и остальные скрытые файлы.

5. **Подготовить схему работы сайта и серверный чек-лист**
   - Добавить в проект отдельную русскоязычную инструкцию: путь запроса от nginx до статической страницы, SPA-fallback, правила для `/assets/`, `/docs/`, `/fonts/`, sitemap и 404.
   - Приложить готовый рекомендуемый блок nginx: gzip/brotli при наличии модуля, immutable-кеш для хешированных assets, `no-cache` для HTML, корректные MIME-типы и запрет отдавать `index.html` вместо отсутствующего PDF/JS/CSS.
   - Описать ожидаемую структуру `dist/client` и команды проверки на сервере, чтобы можно было сопоставить её с фактической конфигурацией.

## Проверка результата

- Автотесты Markdown-парсера и существующие тесты проекта.
- Проверка локальной production-сборки и состава `dist/client`.
- Playwright на 390×844, 768×1024 и 1280×1800: первая отрисовка, положение подвала, блог при прокрутке, таблица в статье.
- Проверка без JavaScript: главная и статьи должны содержать основной текст и сохранять нормальную высоту.
- Контроль запросов к HTML, хешированному JS/CSS, PDF и шрифту с проверкой `Content-Type`, `Content-Encoding` и `Cache-Control`.
