# Ускорить загрузку сайта на сервере

## Что показала проверка боевого домена

- Главная отдаётся за 0.29 с, PDF отдаются корректно (`application/pdf`), все JS/CSS доступны (200). Сайт не «висит» из-за PDF: `pdf-lib` и шрифты PT Sans в главный бандл не попадают — они грузятся только на страницах договора/КП.
- Реальная причина медленной загрузки — вес и отдача статики:
  - **nginx не отдаёт сжатие.** В ответе нет `Content-Encoding`, файлы идут «как есть»: главный JS — 885 КБ, CSS — 119 КБ, плюс ~15 мелких чанков. На мобильном это единицы секунд белого/чёрного экрана.
  - **Нет заголовков кеширования.** Только `ETag`, без `Cache-Control`, поэтому при каждом заходе браузер переспрашивает все файлы.
  - **Главный чанк раздут данными.** В нём ~105 тыс. символов русского текста: `src/data/services.ts` (68 КБ), `src/data/images.ts` (30 КБ) и часть контента подтягиваются в общий чанк через `__root.tsx` и `src/lib/all-routes.ts` (последний импортирует весь блог, 170 КБ).

## Что сделаем

1. **Разгрузить главный бандл**
   - Убрать из `src/routes/__root.tsx` импорт полного массива `SERVICES` (он нужен только для блока «популярные услуги» на 404) — заменить на короткий локальный список ссылок.
   - Разорвать цепочку `src/lib/all-routes.ts` → `src/data/blog.ts` для клиентского кода: вынести список маршрутов в данные, которые нужны только скриптам сборки и sitemap, чтобы блог (170 КБ) не тянулся на каждую страницу.
   - Проверить `src/data/images.ts`: оставить в общем чанке только то, что реально нужно шапке/подвалу.
   - Цель — главный чанк меньше ~350 КБ до сжатия.

2. **Ускорить первую отрисовку**
   - Добавить `preload` для LCP-изображения главной в `head()` маршрута `src/routes/index.tsx`.
   - Убедиться, что тяжёлые интерактивные блоки (калькулятор, формы, карусели) на главной подключаются лениво, а не в основном чанке.

3. **Настройка сервера (дам готовый блок, применяете на сервере)**
   - Включить gzip/brotli для js/css/svg/json/xml — это даст сокращение ~885 КБ → ~200 КБ.
   - Добавить `Cache-Control: public, max-age=31536000, immutable` для `/assets/*` (имена файлов с хешем) и `no-cache` для html.
   - Сохранить текущий SPA-fallback только для html-запросов.

4. **Проверка**
   - Локальная сборка, сравнение размеров чанков до/после.
   - После деплоя — контрольные запросы: главная, `/blog`, `/docs/dogovor-obrazec.pdf`, `/kp` (проверяем `Content-Encoding: gzip` и вес главного чанка).

## Технические детали

- Затрагиваемые файлы: `src/routes/__root.tsx`, `src/lib/all-routes.ts`, `src/routes/index.tsx`, при необходимости `src/data/images.ts` и `scripts/generate-static.mjs` (чтобы sitemap продолжал видеть блог).
- Изменения в логике расчётов, договорах и КП не затрагиваются.
- Конфигурация nginx выдаётся текстом — в репозитории её нет, править сервер из проекта нельзя.
