# Токен бота в env-файл, который вы заполняете сами

## Идея

Токен нигде не хранится в репозитории. Он живёт в одном env-файле на сервере — `/etc/dez-federation/lead.env`. Вы вставляете значение один раз, деплой его больше не перетирает.

```text
/etc/dez-federation/lead.env   <- вы вставляете токен один раз
   |
   v
systemd (lead-api.service, EnvironmentFile)
   |
   v
server/lead-api.ts  ->  api.telegram.org  ->  группа -5244841627
```

## Что меняю в коде

1. `.github/workflows/deploy.yml`
   - Убираю безусловную перезапись `lead.env` из GitHub Secret.
   - Новая логика: если файла нет — создаю заготовку с пустым `TELEGRAM_BOT_TOKEN=` и правами 600; если файл есть — не трогаю (ваше значение сохраняется).
   - Если в GitHub всё же задан секрет `TELEGRAM_BOT_TOKEN`, он используется как запасной источник и подставляется только при пустом токене.
   - Если токен пуст, деплой сайта продолжается, но в лог пишется понятное предупреждение и сервис заявок не перезапускается впустую.

2. `deploy/lead.env.example` — новый файл-образец (без реального значения):

```text
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=-5244841627
LEAD_API_PORT=8787
```

3. `server/lead-api.ts` — при старте без токена сервис не падает молча: отвечает 503 на `/api/lead` и пишет в лог, что токен не задан. `/health` показывает `{"ok":true,"token":false}`, чтобы сразу было видно причину.

4. `.gitignore` — добавляю `.env` и `lead.env`, чтобы токен нельзя было закоммитить случайно.

5. `SERVER_DEPLOYMENT.md` — раздел «Приём заявок» переписываю под новый порядок: как вставить токен, как проверить.

## Что делаете вы (один раз, на сервере)

```bash
mkdir -p /etc/dez-federation
nano /etc/dez-federation/lead.env
```

Вставляете:

```text
TELEGRAM_BOT_TOKEN=сюда_ваш_токен
TELEGRAM_CHAT_ID=-5244841627
LEAD_API_PORT=8787
```

Затем:

```bash
chmod 600 /etc/dez-federation/lead.env
systemctl restart lead-api
curl -s http://127.0.0.1:8787/health
```

Ожидается `{"ok":true,"token":true}`.

## Технические детали

- Файл читается systemd через `EnvironmentFile`, процесс получает токен как переменную окружения — в бандл фронтенда он попасть не может.
- Права 600, владелец root: токен недоступен другим пользователям сервера.
- Ротация токена: меняете строку в файле и делаете `systemctl restart lead-api`, передеплой не нужен.
