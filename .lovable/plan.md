# Полная информация в заявке Telegram

Сейчас в сообщение попадает не всё: страница передаётся, но выводится сокращённо, нет источника перехода (реклама/поиск), нет названия блока/формы, откуда пришла заявка, а в запросе документов не видно, какие именно документы нужны.

## Что будет в каждой заявке

- Тип: заявка на обработку / запрос документов
- Кто: имя, телефон (кликабельный), организация и ИНН (для юрлиц)
- Что: услуга (вредитель), объект, для документов — список выбранных документов
- Почему такая цена: расчётная цена «от …» + расшифровка (услуга × объект по прайсу калькулятора)
- Откуда: страница (URL), название блока/формы («Герой», «Модальное окно», «Страница услуги …»), реферер, метки рекламы (utm_source/medium/campaign/term/content, yclid/gclid)
- Когда и с чего: время по Новосибирску, устройство (мобильный/десктоп), пометка «отправлено из офлайн-очереди», если заявка долежала

## Как это сделать

1. `src/lib/leadSender.ts` — расширить `LeadPayload`: `formName`, `docs?: string[]`, `priceBasis?: string`; в `buildLeadBody` автоматически собирать `referrer`, utm-метки (из `location.search`, с сохранением при первом заходе в `sessionStorage`), `device`, `page`, `sentAt`.
2. `src/components/site/LeadForm.tsx` — передавать `formName` (из `variant`/`title`) и `priceBasis` вида «Клопы · 2-комн. квартира — прайс калькулятора».
3. `src/components/site/DocsRequest.tsx` — передавать выбранные документы и `formName`.
4. `server/lead-api.ts` — в `buildMessage` добавить блоки «Кто / Что / Цена / Источник», экранировать HTML, обрезать длину, показывать UTM только при наличии, помечать «⏳ из офлайн-очереди», если `sentAt` заметно раньше времени приёма.
5. Тесты в `src/lib/__tests__/leadSender.test.ts`: сбор utm/referrer, сохранение меток между страницами, наличие всех полей в теле запроса.

Во внешнем виде сайта ничего не меняется — только состав данных в уведомлении.
