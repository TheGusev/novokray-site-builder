## Проблема

В подвале ссылка «Карта сайта» ведёт на `/sitemap.xml` — это технический файл для поисковых роботов (Google, Yandex). Пользователь видит «простыню» URL без оформления — это нормально для XML, но плохо как UX.

## Решение

Оставить `/sitemap.xml` для поисковиков (он нужен для SEO/GEO), но в подвале вести пользователя на новую человекочитаемую HTML‑страницу.

### 1. Новая страница `src/routes/karta-sayta.tsx` (URL `/karta-sayta`)

Структурированный список всех разделов сайта со ссылками и краткими описаниями:

- **Главные разделы**: Главная, Услуги, Цены, О компании, Гарантии, Контакты, FAQ, Блог, Политика, Соглашение
- **13 услуг** (берём из существующего источника `SERVICES`/данных услуг) — карточки/список со ссылками на `/services/{slug}`
- **Категории по городу** (если есть в данных) — `/category/{slug}`
- **Статьи блога** — список всех постов со ссылками на `/blog/{slug}` и датой

Используем `<Link to=...>` (TanStack Router), семантические `<nav>`, `<h1>`, `<h2>`, `<ul>`. Добавляем `head()` с уникальным title/description, canonical, JSON-LD `SiteNavigationElement`. Подключаем `Breadcrumbs`.

### 2. Подвал `src/components/site/Footer.tsx`

Заменить `<a href="/sitemap.xml">Карта сайта</a>` на `<Link to="/karta-sayta">Карта сайта</Link>`. Ссылку на `/sitemap.xml` не показываем — она остаётся доступна роботам через `robots.txt`.

### 3. Sitemap и навигация

- Добавить `/karta-sayta` в `src/routes/sitemap[.]xml.ts` (changefreq monthly, priority 0.3).
- Никаких изменений в данных, бизнес‑логике, бэкенде.

## Технические детали

- Файлы создать: `src/routes/karta-sayta.tsx`
- Файлы изменить: `src/components/site/Footer.tsx`, sitemap‑роут (для регистрации новой страницы)
- Источник списков услуг/блога — те же модули, что использует `/services` и `/blog` сейчас (прочитаю при сборке)
- Дизайн в стиле остальных страниц: контейнер, заголовок H1, разделы H2, ссылки `text-primary hover:underline`
