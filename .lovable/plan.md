
## Проблема
На мобильном hero текст ложится прямо на фото (бригада в форме) — белый по светлым/пёстрым местам сливается, читается плохо. Сейчас весь блок появляется одной волной (WaveText + Reveal), без последовательного построения.

## Цель
1. Текст всегда читается на любом фоне — за счёт локальной подложки/градиента под текстом, а не глобального затемнения всей картинки.
2. Появление — постепенное, по смысловым кускам, с лёгкими въездами слева/справа.

## Что меняется (только hero на главной)

### 1. Читаемость (src/routes/index.tsx, секция HERO)
- Поверх фото добавить «текстовую плашку»: на мобайле почти на всю ширину, на десктопе ~60%. Это полупрозрачный тёмный слой с лёгким блюром только под колонкой с текстом — не на всю картинку.
  - класс контейнера колонки: `relative rounded-2xl bg-black/45 backdrop-blur-md ring-1 ring-white/10 p-5 md:p-7 md:bg-black/35`
  - дополнительный мягкий градиент снизу плашки → ноль, чтобы край не «обрезал» фото.
- Общее затемнение фото убрать/смягчить (`from-black/55` → `from-black/30`), потому что контраст теперь даёт плашка.
- Заголовок и абзац — белый, тень мелкая (`text-shadow: 0 1px 2px rgba(0,0,0,.4)`) для подстраховки.

### 2. Поэтапная анимация
Заменить текущий WaveText/Reveal на единый сценарий с фиксированными задержками:

```
0.00s  badge "Бригады свободны"   — fade + slide-down
0.20s  H1, строка 1 "Санитарная служба"  — слова по очереди слева (stagger 60ms)
0.55s  H1, строка 2 "№1 в Новосибирске"  — слова по очереди справа (stagger 60ms)
1.05s  подзаголовок — по предложениям (3 шт.), каждое fade+slide-up с задержкой 180ms
1.75s  кнопки CTA — fade-up
2.00s  блок счётчиков (38 000+ / 4.9 / 24 мес) — fade-up, потом CountUp
```

- Реализация: один новый маленький компонент `HeroReveal` (или просто inline-классы с `style={{ animationDelay }}`) на базе уже существующих keyframes `fade-in` в Tailwind-конфиге и существующего `useReveal` для триггера «когда секция в зоне видимости».
- Для «слов» в H1 — разбиваем строку на массив слов, оборачиваем в `<span class="inline-block opacity-0 animate-fade-in" style={{ animationDelay, animationFillMode: 'both' }}>`. Направление — у первой строки `translateX(-12px)→0`, у второй `translateX(12px)→0` (новый keyframe `slide-in-left-sm` / `slide-in-right-sm` в styles.css, очень короткое смещение, чтобы не «улетало» за экран).
- Подзаголовок: текст разделяем точкой на 3 предложения, каждое — `block` с собственной задержкой.
- WaveText из hero убираем (он мешает восприятию и плохо ложится на занятый фон). Сохраним его для других мест, если используется.
- `prefers-reduced-motion` — мгновенный показ без задержек (как уже сделано в стилях для wave-text).

### 3. Технические детали
- Файлы: только `src/routes/index.tsx` (hero JSX) и `src/styles.css` (2 новых keyframes + утилиты `.animate-slide-in-left-sm`, `.animate-slide-in-right-sm`, `.text-shadow-hero`).
- Никаких изменений в роутинге, данных, SEO, других секциях.
- Высота hero не растёт: плашка добавляет только padding ~16–24px.

## Что НЕ меняется
- Фото бригады остаётся.
- Бейдж, CTA-кнопки, счётчики — те же тексты и ссылки.
- WaveText.tsx, AnimatedHeading.tsx — не трогаем (используются в других секциях).

## Результат
- Текст читается на любом устройстве за счёт локальной тёмной плашки с блюром.
- При открытии главной взгляд ведётся последовательно: бейдж → заголовок (слева→справа) → описание по предложениям → CTA → цифры.
- Анимация длится ~2 сек, не блокирует взаимодействие (CTA доступен сразу).
