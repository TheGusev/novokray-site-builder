## Что сделаем

### 1. Расширим каталог вредителей (`src/data/treatmentCatalog.ts`)

Добавим уличные/участковые виды:

- **Клещи** — обработка участка (м²), периметр (м.п.), тропы/зоны отдыха, барьер 21 дн. Препараты: Медилис-Ципер, Таран, Сипаз-Супер, Цифокс.
- **Комары** — обработка участка (м²), кустарники/деревья (шт), водоёмы (точка), барьер 30 дн. Препараты: Медилис-Ципер, Сипаз-Супер, Биоцифен, Цифокс.
- **Мошка / гнус** — обработка участка (м²), прибрежная зона (м.п.), кустарники (шт). Препараты: Медилис-Ципер, Сипаз-Супер.
- **Мухи** — пролив мусорных зон, оконные/дверные проёмы, обработка туманом. Препараты: Агита, Лямбда-Зона.
- **Муха-горбунья / дрозофилы** — точечная обработка (по желанию, можно объединить с мухами; решу при имплементации).

Поле `area` у вредителей-«уличников» — пометим как `outdoor: true` для подсказок.

### 2. Метаданные элементов для валидации

В `TreatmentElement` добавим:
- `min`, `max`, `step` — допустимые границы количества по единице измерения (например, `м²`: 1–10000, шаг 1; `м.п.`: 1–500; `шт`: 1–50; `комн.`: 1–20; `точка`: 1–50; `комплект`: 1–10).
- `hint` — короткая подсказка («измеряется в погонных метрах по периметру комнаты» и т.п.).
- `levelLock?: InfestationLevel[]` — для позиций, которые имеют смысл только при определённой степени (напр. «контрольный визит» — при 4-5; «гель-приманка» — при 1/2-3). Используется как мягкое предупреждение, не блокировка.

### 3. Валидация и подсказки в форме (`src/routes/dogovor.zapolnit.tsx`)

- **Числовые поля количества**: `type="number"` + `min`/`max`/`step` из каталога, при выходе за границы — `<Alert variant="destructive">` под полем с текстом «Для м.п. укажите 1–500». Авто-clamp на blur.
- **Единицы измерения**: бейдж рядом с количеством (`шт`, `м.п.`, `м²`, `комн.`, `точка`, `комплект`) — невозможно перепутать.
- **Подсказка под чекбоксом работы**: маленький `text-muted-foreground` с `element.hint`.
- **Соответствие «степень ↔ работы»**:
  - При смене степени проверяем выбранные работы. Если работа с `levelLock` не подходит — показываем жёлтый `Alert` («Контрольный визит обычно нужен только при сильном заражении 4-5») с кнопкой «Убрать».
  - При степени 4-5 и невыбранной «барьерной защите» — мягкая подсказка «Рекомендуем добавить барьер при сильном заражении».
  - Для уличных вредителей — подсказка «Укажите площадь участка в м²» и предупреждение если выбрана только «комн.» (не применимо для улицы).
- **Препараты**: если выбрано 0 препаратов — предупреждение «Выберите хотя бы один препарат». Лимит — макс 5 препаратов на блок (защита от опечаток).
- **Гарантия**: уже авто; добавим подсказку «Срок установлен по степени, можно изменить вручную».
- **Итоговая валидация перед PDF**: блокируем «Сгенерировать договор» если есть ошибки (красные алерты). Показываем сводку «Исправьте: 2 ошибки в блоке Клопы». Жёлтые предупреждения не блокируют.

### 4. PDF (`src/lib/dogovor/buildPdf.ts`)

Без структурных изменений — единицы и количества уже корректно выводятся. Только убедимся, что при `outdoor: true` в названии блока подставляется «(участок)» для ясности.

### 5. Из чего НЕ трогаем

- Дизайн-токены, шапка/подвал, лид-форма на главной, серверная часть.
- Lovable Cloud не подключаем — всё клиентом.

## Технические детали

Валидация — чистый React state + Zod-схема на сабмит (минимальная, локально в файле формы, без новых зависимостей: zod уже стоит). Подсказки — `<p class="text-xs text-muted-foreground">`, ошибки — компонент `Alert` из shadcn. Бейджи единиц — `Badge` shadcn.

## Что НЕ делаем

- Не делаем админку для редактирования каталога.
- Не выносим каталог в БД.
- Не меняем формулы множителей и гарантий.
