# Цели Яндекс.Метрики и составная цель по каждой услуге

Сейчас на сайте стоит счётчик 110968995, но ни одна цель не отправляется: Метрика видит только визиты. Сделаем такой же слоёный подход, как в примере — один источник правды в коде, атомарные цели в точках действия, и составные цели на стороне Метрики.

## Слой 1. Источник правды

Новый файл `src/lib/analytics.ts`:

- `trackGoal(name, params?)` — безопасная обёртка над `window.ym(110968995, 'reachGoal', ...)`: не падает, если Метрика не загрузилась или код выполняется на сервере; в dev пишет в консоль.
- Автоматически добавляет в параметры контекст: страницу, устройство, utm-метки (переиспользуем `collectUtm()` из `src/lib/leadSender.ts`).
- Все имена целей — константами в одном месте, чтобы они не расходились по коду.

## Слой 2. Точки вызова

Атомарные цели (только осознанные действия, без скроллов и просмотров страниц):

| Цель | Где срабатывает |
|---|---|
| `lead_hero` | форма в первом экране |
| `lead_modal` | форма в модальном окне |
| `lead_service` | форма на странице услуги / города / района |
| `lead_price` | форма из блока прайса и калькулятора |
| `docs_request` | запрос документов |
| `kp_submit` | заявка юрлица на странице `/kp` |
| `kp_pdf`, `invoice_pdf` | скачивание КП и счёта |
| `dogovor_pdf` | скачивание договора |
| `call_click` | клик по телефону (шапка, подвал, контакты) |
| `telegram_click` | клик по Telegram |

Плюс цели с префиксом по услуге — в них и есть «составная цель на каждую услугу»:

```text
lead_<pest>  →  lead_klopy, lead_tarakany, lead_gryzuny, lead_kleshchi, ...
```

Ключ вредителя берём из существующих справочников (`src/data/services.ts` / `servicesIndex.ts`) и приводим к латинскому slug, чтобы имена целей были стабильными.

Каждая отправка лида шлёт две цели: по форме (`lead_hero` и т.п.) и по услуге (`lead_klopy`), с параметрами: услуга, объект, расчётная цена, название формы, страница, utm.

## Слой 3. Настройка в Метрике

Составные цели в коде не описываются — их собирают в интерфейсе счётчика. Подготовлю пошаговый список, что создать:

1. Все атомарные JavaScript-цели из таблицы выше.
2. Составная цель `all_conversions` = все `lead_*` + `docs_request` + `kp_submit`.
3. Составная цель на каждую услугу: `conv_klopy` = `lead_klopy` + звонок со страницы этой услуги, и так по каждому вредителю из каталога.
4. Составная цель `contacts` = `call_click` + `telegram_click`.

Инструкцию положу в `SERVER_DEPLOYMENT.md` (раздел «Аналитика»), чтобы её можно было выполнить в кабинете Метрики за один заход.

## Технические детали

- `src/lib/analytics.ts` — новый модуль, типизированный `window.ym`, безопасный при SSR и пререндере.
- `src/lib/leadSender.ts` — переиспользуем `collectUtm`, добавим хелпер slug услуги.
- Правки только в обработчиках: `LeadForm.tsx`, `DocsRequest.tsx`, `Header.tsx`, `Footer.tsx`, `routes/kp.tsx`, `routes/dogovor.zapolnit.tsx`, `routes/contacts.tsx`. Внешний вид не меняется.
- Тесты в `src/lib/__tests__/analytics.test.ts`: цель не падает без `ym`, название услуги превращается в корректный slug, в параметрах есть utm и страница.
