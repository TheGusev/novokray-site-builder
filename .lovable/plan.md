# План исправления

Проблема воспроизвел: сейчас карточки документов ведут напрямую на raw PDF asset. На телефоне браузер открывает встроенный PDF viewer поверх сайта, поэтому пользователь не видит кнопки возврата внутри интерфейса сайта.

## Что изменю

1. **Сделаю отдельную страницу просмотра документов внутри сайта**
   - Добавлю route для документа с нормальной шапкой сайта.
   - На странице будет явная кнопка **«Назад на сайт»** и отдельная кнопка **«Скачать PDF»**.
   - Сам PDF будет открываться внутри страницы, а не прямым переходом на asset.

2. **Переделаю блок «Образец договора и журнал СанПиН»**
   - Карточки документов будут вести не на raw PDF, а на внутреннюю страницу просмотра.
   - Поведение станет одинаковым на мобильных и десктопе.

3. **Проверю UX возврата**
   - Если пользователь зашел с `/garantii`, кнопка вернет его назад на страницу сайта.
   - Если документ открыт напрямую по ссылке, кнопка поведет на безопасную страницу сайта, а не в никуда.

4. **Проведу повторную проверку**
   - Мобильный сценарий: открыть документ, увидеть кнопки, вернуться на сайт.
   - Проверю все 4 документа, чтобы поведение было одинаковым.

## Технически

- Обновлю `DocsRequest.tsx`, чтобы ссылки шли на внутренний route.
- Добавлю новый route для просмотра документа, например в формате `/docs/$slug`.
- Использую общий источник данных для названия документа, файла и URL, чтобы не дублировать логику.
- Сохраню возможность прямого скачивания PDF отдельной кнопкой.

## Результат

После этого документ будет открываться как часть сайта, и пользователь всегда увидит понятный способ вернуться назад.
