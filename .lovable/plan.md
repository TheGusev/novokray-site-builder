# Куда именно вставить токен бота

## Важное ограничение

Токен, вставленный в чат Lovable, попадает в хранилище секретов Lovable Cloud. Ваш сайт работает не там — он собирается GitHub Actions и выкатывается на ваш сервер по SSH. Секрет Lovable на этот сервер физически не попадает, поэтому сам по себе он заявки не включит.

Рабочих путей два.

## Вариант A (рекомендую): GitHub Secret

Один раз добавить токен в репозиторий:

1. GitHub → репозиторий `novokray-site-builder` → **Settings → Secrets and variables → Actions → New repository secret**
2. Имя: `TELEGRAM_BOT_TOKEN`, значение — токен бота
3. Любой следующий push (или ручной запуск workflow) сам впишет токен в `/etc/dez-federation/lead.env` — эта логика в деплое уже есть

Плюс: токен нигде не хранится в коде, ротация — заменой одного секрета в GitHub.

## Вариант B: вставить вручную на сервере

```bash
nano /etc/dez-federation/lead.env      # TELEGRAM_BOT_TOKEN=...
chmod 600 /etc/dez-federation/lead.env
systemctl restart lead-api
curl -s localhost:8787/health          # ожидается {"ok":true,"token":true}
```

Деплой этот файл не перетирает, значение сохраняется между выкатами.

## Что делаю я после вашего решения

- Если выбираете A или B — правок в коде не нужно, всё уже готово; я только проверю `/health` и помогу с диагностикой, если заявки не дойдут.
- Если всё же хотите отдать токен через чат — открою защищённую форму и сохраню его в секретах Lovable, но тогда придётся дополнительно продублировать значение в GitHub Secret, иначе сервер его не увидит. Дублирование секрета в двух местах усложняет ротацию, поэтому рекомендую вариант A.

## Проверка результата (в любом варианте)

```bash
systemctl status lead-api
curl -s http://127.0.0.1:8787/health
```

Затем отправить тестовую заявку с сайта и убедиться, что сообщение пришло в группу `-5244841627`.
