## Что сделаем

Новая страница `/dogovor/zapolnit` — открытый конструктор: менеджер/мастер вводит данные клиента и услуги (тот же UX, что в основном калькуляторе), получает заполненный PDF на основе текущего `dogovor-obrazec.pdf` (наложение через pdf-lib).

Доступ открытый, ссылка добавится в раздел документов (`/garantii` и страница `/docs/dogovor`) — кнопка «Заполнить договор».

## Структура формы

Слева — форма, справа — живой превью договора (HTML-копия раскладки) + большой CTA «Скачать PDF».

**Блок 1. Договор**
- № договора — автогенерация `ДФ-{YYYYMMDD}-{случ. 4 цифры}`, можно перезаписать
- Дата договора — сегодня по умолчанию

**Блок 2. Заказчик**
- Тип: Физлицо / Юрлицо (переключатель)
- Физлицо: ФИО, телефон, паспорт (серия+номер, кем выдан, дата), адрес объекта
- Юрлицо: наименование, ИНН, КПП, юр. адрес, контактное лицо, телефон, адрес объекта

**Блок 3. Услуги** (как в калькуляторе)
- Список строк, каждая: «Вредитель» (select из `PRICING`) → «Объект» (select из доступных для этого вредителя) → авто-подстановка цены «от» из `leadPricing.ts` + поле «Кол-во» + поле «Цена за ед.» (редактируется)
- Кнопки «+ добавить услугу», «удалить»
- Альтернатива «Своя услуга» — свободный ввод названия + цена + кол-во
- Итог суммы считается автоматически

**Блок 4. Исполнитель и условия**
- ФИО мастера (text)
- Гарантийный срок — select: 30 / 60 / 90 / 180 дней (default 30)
- Способ оплаты — radio: Наличные / Перевод / Карта / Безнал (юрлицо)
- Подпись мастера — загрузка картинки (PNG с прозрачностью), сохраняется только в памяти браузера, накладывается на PDF

## Генерация PDF

Стек: `pdf-lib` + `@pdf-lib/fontkit` + кириллический шрифт (PT Sans Regular/Bold, .ttf, загружаем как ассет через lovable-assets — встроенные шрифты pdf-lib не поддерживают кириллицу).

Алгоритм:
1. Загружаем `dogovor-obrazec.pdf` по `DOCS[dogovor].url`.
2. Через `PDFDocument.load()` открываем как шаблон.
3. Регистрируем fontkit, встраиваем PT Sans.
4. На каждой странице `drawText()` поверх образца в заранее размеченных координатах (X/Y).
5. Таблица услуг — рисуем сами строками; если строк больше 6 — `addPage()` с шапкой «Приложение №1».
6. Подпись мастера — `embedPng()` + `drawImage()` в зоне подписи.
7. Итоговая сумма прописью — генерируем через мини-функцию `rubInWords()` (без зависимостей).
8. `pdfDoc.save()` → `Blob` → `URL.createObjectURL` → `<a download="Договор-{№}.pdf">`.

**Калибровка координат.** Шаблон фиксированный → координаты задаются константой `FIELD_COORDS` в `src/lib/dogovor/coords.ts`. Делаем dev-режим (`?debug=1` в URL) — рисует красную сетку 10pt и подписывает X/Y, чтобы быстро откалибровать поля в превью.

## Валидация (zod)

- ФИО заказчика: 2–120 симв., только буквы/пробел/дефис
- Телефон: формат `+7 (XXX) XXX-XX-XX`
- ИНН: 10 или 12 цифр (валидируется по контрольной сумме)
- Адрес: 5–250 симв.
- Минимум одна услуга, цена > 0, кол-во ≥ 1
- Подпись: PNG/JPG ≤ 1 MB

## SEO / приватность

- `<meta name="robots" content="noindex, nofollow">` — страница рабочая, не для индексации
- `Disallow: /dogovor/zapolnit` в `robots.txt`
- Никакие данные не уходят на сервер — всё считается и собирается в браузере; в `sendLead.ts` ничего не добавляем

## Что НЕ делаем

- Сохранение договоров в БД (нет требования)
- Печать с QR-кодом
- Электронная подпись клиента
- Загрузка реквизитов из ЕГРЮЛ по ИНН (можно отдельной итерацией)
