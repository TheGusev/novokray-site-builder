# План: синхронизация чипов вредителей и корректный расчёт цены

## Цель
Убрать потерю/дублирование данных при повторном выборе того же вредителя через мультиселект и гарантировать правильный расчёт итога (включая барьер и ручные цены) при нескольких вредителях.

## Что меняем в `src/routes/dogovor.zapolnit.tsx`

### 1. Синхронизация чипов ↔ блоки
- Ввести кэш удалённых блоков `graveyard: Record<PestKey, TreatmentBlock[]>` в состоянии.
- При **снятии** чипа: перенести все блоки этого вредителя в `graveyard` (сохраняются работы, кол-во, препараты, ручные цены, барьер, степень).
- При **выборе** чипа: если в `graveyard` есть блоки — восстановить их; иначе создать один новый пустой блок.
- Кнопка «Дублировать блок» продолжает работать: создаёт новый блок того же вредителя без затрагивания графьярда.
- При наличии нескольких блоков одного вредителя снятие чипа спрашивает подтверждение («Убрать все N блоков?»).

### 2. Отображение чипов
- На чипе показывать счётчик, если блоков > 1 (например «Клопы ×2»).
- Активные чипы визуально отделены; порядок стабильный (по каталогу).

### 3. Расчёт стоимости (multi-pest)
- `blockSum(block)` = Σ (manualPrice ?? unitPrice × qty × levelMultiplier) по выбранным работам + барьер (если включён, добавляется один раз на блок).
- `totalSum` = Σ `blockSum` по всем блокам всех вредителей.
- Ручная цена перекрывает как базовую, так и множитель степени — это фиксируется в подсказке под полем.
- Барьер: цена берётся из каталога по вредителю; при отсутствии — чекбокс скрыт.
- В сводке справа блоки нумеруются в рамках вредителя («Клопы · блок 2»), если их больше одного.

### 4. Договор/PDF
- В `buildPdf.ts` итерация уже по массиву блоков — проверяем, что заголовки и итоги отражают несколько блоков одного вредителя (нумерация) и что `manualPrice`/барьер учтены единым образом с UI.

## Технические детали
- Тип блока: `{ id, pest, level, works: Record<workId, {qty, manualPrice?}>, preparations: string[], barrier: boolean }`.
- Все мутации через `setBlocks` иммутабельно; graveyard хранится отдельным `useState`, не сериализуется в PDF.
- Юнит-тесты на `blockSum`/`totalSum` для сценариев: несколько вредителей, ручная цена, барьер, множитель степени — в `src/data/__tests__/treatmentCatalog.test.ts` (добавить блок «pricing multi-pest»).
